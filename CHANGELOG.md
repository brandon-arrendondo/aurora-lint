# Changelog

All notable changes to aurora-lint are documented here, for people who use
the tool. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
with four headings per release: **Added** (a new rule, option, output or
capability), **Changed** (a change in what existing output or options mean),
**Fixed** (a misfire, crash, wrong result or change in what a scan reports)
and **Removed** (anything you could have depended on that is gone).
Internal work -- benchmarks, adjudication, refactors, CI, docs -- is not
listed; the git history is the archive for that.

**Versions here are published releases**, not every version the crate passed
through. aurora-lint bumps the patch version on nearly every commit, and only
tagged versions are built, signed and published, so a section covers every
change since the previous release. The 0.4.x line shipped from a private
repository and is consolidated here by release, not by patch version.

The `[Unreleased]` section is maintained by `scripts/generate_changelog.py`
from release notes written on the project's task records; the dated sections
are curated by hand. See `docs/adr/0009` for what belongs here and
`docs/adr/0007` for what may never appear here.

What to check or change when moving from one release to the next (exit
statuses, presets, renamed rules, suppressions) is in `docs/upgrading.rst`.

## [0.7.0] - 2026-10-31

### Added

- A configuration file, `--rules` list or suppression (suppress.toml or an inline comment) that names a rule aurora-lint no longer ships now loads with one warning saying which release removed the rule, why, and which rules report its construct instead, where before a `--rules` list or suppression naming one silently matched nothing; the name still matches nothing, and a configuration's section for it is ignored. The new `--list-rules [text|json]` option lists every rule the tool ships, whether the configuration enables it, and every removed rule with its reason.
- A new ENV33-C option, env33_locally_constructed_command_allowed, controls whether a system() or popen() call whose command no untrusted input can reach is reported. It is on under the default preset and off under strict and pedantic.
- A CWE ruleset, configured under `[rules.cwe.<ID>]` and enabled by default, for weaknesses CERT C has no identifier for: CWE-327 (a weak cipher such as DES, 3DES, RC2, RC4 or RC5 selected through Windows CryptoAPI or OpenSSL), CWE-428 (an unquoted `CreateProcess*` command path containing a space), CWE-272 (a registry write under HKEY_LOCAL_MACHINE or HKEY_CLASSES_ROOT) and CWE-666 (socket calls out of order on one socket). `--list-rules` lists them with the CERT C rules.
- An internal error in one rule on one file no longer stops the whole scan with no output: that rule's findings for that file are omitted, every other finding is kept, and the failure is reported on stderr and as a SARIF tool-execution notification. A rule that fails on three files is dropped for the rest of the scan. Files that are not C source (binaries, archives, files with NUL bytes) or are larger than --max-file-size are skipped and reported instead of parsed. New --rule-step-limit, --rule-time-limit and --max-file-size options set the bounds.
- Headers that a scan cannot find are now reported. A one-line stderr summary names how many were not found and the first few. Headers that live in the compiler's built-in and multiarch directories, which the scan searches only with `--system-includes`, are counted separately. `-v` lists each one with the file and line that includes it, SARIF exports carry them as a run property and a `note`, and `--report-headers FILE` writes them all as JSON, with the SHA-256 of every header read from outside the project, so two hosts' reports can be diffed to the header behind a difference in their findings.
- Findings that may depend on a header the scan could not find say so: `missing_headers` in the JSON export and `properties.missingHeaders` in SARIF list the missing headers that a project file in the finding's include graph names. A finding whose line uses a macro that only a header outside the project defines carries `harvested_from` (`properties.harvestedFrom`), naming the macro and the header. With `-v` both appear as notes under the finding. Neither changes which findings are reported.
- --diff-base REF scans the C files changed between the merge base of REF and HEAD, plus uncommitted and untracked ones, so a pull-request job in a clean CI checkout scans what the branch changed. It implies --diff and needs REF and the history back to the merge base (fetch-depth: 0 in a shallow clone).
- New `--generated-include DIR` (repeatable) declares a build tree whose headers the build generated for one configuration. Their declarations, macro values and inline bodies are applied only to the files that configuration compiles, as the compile database names them, and only to the `#if` arms it compiles; every other file or arm is analysed as if those headers were missing. A compile database's include directories in an entry's build tree outside the scanned tree are recognised without the flag. Scans with no generated headers are unchanged.
- A third settings preset, `--profile pedantic`, reads a rule beyond its text where the rule has a stricter sound reading, and may decline a rule; until a rule gains a pedantic reading it is read as `--profile strict` reads it.
- New optional target facts `libc_version`, `c_standard` and `posix_version`, and a `newlib-nano` library model; each enters the settings hash only when declared.
- The pedantic preset trusts only a C library you declare. With none declared it still scans, prints a warning naming the `libc` setting and the rules that depend on library behaviour, records `libc_declared: false` in the SARIF/JSON settings, and `--check-config` warns.
- --max-nesting-depth: a file nested more than 5000 levels deep is now skipped and reported (exit 3) instead of crashing the scan with a stack overflow.
- New environment option signal_handlers_persistent declares that signal() handlers stay installed while they run. SIG34-C now applies its exception for a handler changing its own signal only when this is declared, not when the call sits under an #if.
- A new MSC37-C option, msc37_attribute_noreturn, on under the default preset and off under strict and pedantic, credits the GNU noreturn attribute (`__attribute__((noreturn))` or `[[gnu::noreturn]]`, directly or through a macro) as MSC37-C credits `_Noreturn`.
- A rule's block in a manifest can say why it is disabled, with `disabled_reason = "..."`. `--check-config` lists every rule the configuration disables with that reason, a SARIF export marks each one `defaultConfiguration.enabled: false` with the reason, and `--rules` naming a disabled rule now warns instead of giving a silently clean report; the rules withheld from the default manifest carry one.
- A new `[environment.threads]` table declares the thread API a project uses: `families = ["freertos"]` selects a shipped profile, `functions` and `types` declare the project's own thread, lock, wait and thread-local-storage calls, and `posix = "off"` (or `posix_version = "none"`) stops POSIX threads being read. The concurrency rules now read C11 and POSIX threads alike and recognise calls by declaration rather than spelling: CON34-C covers pthread_create(), CON36-C reports pthread_cond_wait() and the other POSIX waits outside a loop, CON30-C reports a POSIX key or declared slot never freed, POS49-C counts only real lock and unlock calls, CON37-C reports only the standard signal(), and POS50-C reports a local array passed by name and no longer reports a block-scope static.
- The option `flp00_exact_zero_comparison_exempt` controls whether FLP00-C exempts a comparison with an exact zero; it is on under the default policy and off under strict and pedantic, which now report `x == 0.0`.

### Changed

- A declared `closed_program` now also treats a non-static function's call sites in the scanned files as all of its call sites, so what every caller passes proves its parameter safe, as it already did for a `static` function: value ranges, buffer sizes, non-null pointers, untainted or range-checked arguments, and format strings. A function whose address is taken, and `main`, stay open. ENV03-C, ENV33-C and STR02-C, which accept a caller because its body reads no untrusted input, still credit only `static` functions, and so does the INT30-C to INT32-C test of whether a parameter can receive untrusted or full-range input. Before, the option only let EXP33-C fold constants. Scans that don't declare it are unchanged.
- Under --profile strict, ENV33-C now reports every system() or popen() call with a command, as CERT ENV33-C is written, including commands built inside the function from literals.
- A new exit code, 3, means the scan completed but is incomplete: a rule, a file or a file's prescan crashed or ran out of its step or time budget, or an input file was skipped. It takes precedence over exit 1 and is returned with or without --fail-on-violation / --fail-on-severity. CI that checks for exactly 1 should also handle 3 (see docs/error-handling.rst).
- --diff now refuses (exit 2) a PATH that is not the root of a git repository, including a directory outside any repository; before, it silently scanned every C file there.
- The strict preset now assumes only a hosted ISO C library. POSIX and the C and POSIX editions are facts you declare in the configuration or through the project's compile_commands.json, and the scan reports which source each fact came from and any conflict between the two. POSIX contracts and exemptions apply only when POSIX is declared, so a `--profile strict` scan of POSIX code that declares neither now reports the findings those exemptions used to withhold.
- Under the strict preset, `free(NULL)`, `exit`/`abort`/`longjmp` and `main`'s `argv` are trusted unless you declare a different `libc`, functions declared `_Noreturn` are trusted not to return, and PRE31-C no longer treats `strlen`, `memcmp` and similar calls as side-effect-free (option pre31_listed_library_calls_pure).
- Under the default and strict presets, ENV33-C no longer reports Windows `_exec*`/`_spawn*` (option env33_exec_spawn_exempt), and FLP36-C accepts a constant assert over standard limits as a precision check (option flp36_constant_assert_is_guard).
- INT33-C and STR30-C report at severity Low, matching CERT's risk assessment, as MEM04-C already did.
- A rule that the active preset declines, while another preset still enforces it, no longer runs under that preset. The scan summary, the SARIF run settings and `--check-config` name each declined rule and the reason. Today only `--profile pedantic` declines rules: ERR33-C, FIO30-C and POS54-C.
- When no data model is declared, the default preset assumes LP64 on a hosted target, so `1U << 31` and `168 << 16` are no longer reported there. The strict preset credits only ISO C's minimum widths. The pedantic preset does the same and warns that the data model is undeclared. A declared `data_model`, or `-m32`/`-m64` in a compile database, always wins. The scan summary, SARIF run settings and `--check-config` name the data model in force and where it came from.
- The settings hash now includes the active preset's column of the per-rule preset table, so every preset's settings hash, and every run id that carries one, changes once at this release with nothing else changed.
- Under the default preset, POS34-C no longer reports putenv() of an array in `main`'s own frame, or where every path after the call ends the process with exit(), abort() or the like (options pos34_main_frame_exempt and pos34_exit_path_exempt); the strict and pedantic presets report them, as CERT writes the rule.
- MSC37-C is now reported at High severity (was Medium), as CERT rates it.
- FIO21-C reports at severity Medium (was High), as CERT rates it. A new option, fio21_tmpfile_exempt_under_posix, on under the default preset and off under strict and pedantic, leaves tmpfile() unreported where POSIX holds, since POSIX removes the file it creates; tmpnam(), tempnam() and mktemp() are reported under either value.
- EXP30-C, FIO01-C, FIO08-C, FIO30-C, FIO32-C, FLP32-C, INT15-C, MEM35-C, STR34-C and WIN30-C are withheld by default until they are rewritten, because they can report constructs that are not in the code; to run them, enable them in a manifest.
- A SARIF finding's suggestion is now in `properties.suggestion`, not `fixes[].description.text`, since SARIF requires a fix to carry concrete edits.
- PRE01-C reports each unparenthesized use of a macro parameter at the line and column where it is written, instead of once per parameter at the #define, and its message names the macro.
- FIO14-C findings are now Low severity (were Medium), as CERT rates it.
- DCL11-C no longer runs with the default manifest, under any preset, until it is removed, because its type check guesses an argument's type from its name and can report a mismatch for an argument whose type matches. To keep running it, set `enabled = true` in its block in your manifest.
- SARIF reports now give `startColumn` in UTF-16 code units and declare `columnKind` as `utf16CodeUnits`, so a viewer lands on the reported construct on a line with non-ASCII text before it; it used to land late by a column or more per such character. The JSON and terminal output still give a UTF-8 byte column.
- EXP19-C reports each unbraced `if`, `else`, `for` and `while` body where the body starts, not at its keyword, so per-line suppressions of these findings need regenerating.
- MSC39-C is withheld: it no longer runs by default, and reports nothing if enabled. Its 0.6.0 reports named a function that takes a `va_list` by value and calls `va_arg()` on it, which CERT permits, rather than the caller's later use of its own list other than `va_end()`, which is the violation. It returns when it detects that use.
- DCL37-C findings are now Low severity (were Medium), as CERT rates the rule.
- SIG02-C findings for `raise()` are now High severity (were Medium), as CERT rates the recommendation and as `kill(getpid(), ...)` findings already were; the new `pthread_kill()` findings are High too.
- Ignore patterns now match a file extension in any case, as file discovery does, so `gen/*.c` also leaves out `gen/A.C`. This covers `--exclude-all`, `--report-exclude`, `--prescan-exclude`, a manifest's `[scope]` and `toolchain.toml`'s `[ignore].paths`. Directory names and the rest of the file name stay case-sensitive.

### Fixed

- MEM35-C no longer stops the whole scan, with no output, on an allocation size that has an unparenthesized `sizeof` operand followed by a parenthesized one, such as `malloc(n + (sizeof *p) + (sizeof s->field))`.
- Calls to input functions written with a space or line break before the parenthesis, such as `fscanf (stdin, ...)`, now count as reading external input, and calls to functions whose names merely end in an input function's name (such as `thread_read()` or `do_accept()`) no longer do. This changes INT30-C, INT31-C, INT32-C and ENV03-C findings that depend on whether a caller reads external input.
- Function summaries read calls instead of matching text: a function counts as never returning only when it unconditionally calls exit/abort (spacing and parentheses no longer matter), or a macro every definition of which always does. A function no longer counts when it calls a lookalike such as do_exit(), exits on only one branch, or uses an assert-style macro that aborts only when its check fails. A pointer-returning function that returns through a macro now counts as allocating only when it really calls an allocator: `malloc (n)` and allocator-wrapping macros count, and a string mentioning malloc( no longer does.
- EXP34-C no longer skips a dereference that comes before a later NULL test in a function that can be called from outside the scan (external linkage, or a static function whose address escapes) just because every call site in the scanned files passes a valid pointer. Declaring `closed_program` restores the exemption for functions whose address does not escape.
- DCL31-C no longer stops reporting undeclared function calls across a whole project when a system header on the include path names a header that doesn't exist (such as a platform-only include), or when the only missing header is named in an `#if 0` arm.
- The noreturn inference now always follows a chain of wrapper functions that end the program to its end, however deep. A chain deeper than four wrappers used to be resolved fully on some runs and not on others, so findings that depend on where a path ends could differ between two identical runs.
- ENV33-C no longer reports system(NULL), which only checks whether a command processor exists (CERT ENV33-C-EX1).
- CON32-C, FIO22-C, MEM33-C and STR31-C now report the same way on every run of the same code. When a file declared two similarly named structs, files or macros, which one a finding named could change from run to run, and STR31-C could read a buffer's size from a macro whose name merely contained the declared one.
- A malformed #define whose ")" comes before its "(", or a multi-byte identifier used as a divisor, no longer crashes the whole scan in INT33-C.
- Facts carried across function calls (a wrapper frees, stores, closes or clears its argument; a value is tainted; a function returns allocated memory, and similar) now reach the outermost function of a forwarding chain however deep it is, where a fixed pass limit stopped them part way. A use after free through a long chain of free wrappers is now reported, the same memory is no longer reported as leaked, and data tainted at the far end of a long call chain is no longer treated as clean. A macro defined through a chain of other macros written in reverse file order now resolves to its value.
- A configuration that names only CWE-ruleset or BRULE rules, with no CERT C rule table, now loads instead of failing with "missing field `cert_c`".
- Value-range analysis now converges on loops written with a backward goto, and when a function's analysis still doesn't converge it no longer keeps a partial result: integer and array findings in such functions are now reported as if no range were known, instead of being suppressed on a range that was never established.
- DCL31-C no longer reports a call through a function-pointer parameter, local or file-scope variable as an undeclared function when the pointer's typedef isn't visible to the scan.
- INT30-C, INT31-C and INT32-C judge a static function's parameter by what each caller passes at that position, as the caller's own code would be judged, instead of by whether any caller reads input. A full-range value such as rand() or strtoul() passed through a parameter is now reported, and a parameter whose callers pass only locally computed values no longer is.
- Scans of files with very long functions, or with large blocks of comment padding, are much faster; findings are unchanged.
- INT30-C no longer reports an array plus an integer as an unsigned addition that can wrap when the array is declared in a header or is a struct member (including members of nested anonymous structs and members under #ifdef); that is pointer arithmetic.
- A file-scope object declared through a declaration-wrapper macro (a macro whose body is a storage class followed by its parameter) is now known by its declared type, so INT30-C no longer treats such an array as an unsigned integer in arithmetic.
- MEM30-C and MEM31-C no longer treat a macro call as `free` or `malloc` when the call passes arguments those functions cannot take (such as a three-argument `XFREE(p, heap, type)` whose one-argument `#define XFREE free` comes from another library's header), which had produced double-free reports naming the wrong argument and leak reports naming the wrong allocator.
- FIO39-C tracks input and output on each stream separately, so reading one stream and writing another (input from stdin next to messages on stderr, or a loop copying one file into another) is no longer reported as alternating.
- The initialization-state analysis behind EXP33-C now always converges, including in functions that mix goto with declarations in loops, so the "did not converge" warning it printed and recorded in SARIF and JSON output is gone; findings are unchanged.
- DCL31-C no longer stops checking undeclared function calls across a whole project because one part of it includes a build-generated header: it stands down only in the files that may include such a header, says which, and so now reports in the rest of the project; it also no longer mistakes a project header named by its path (such as utils/common.h) that's merely off the search path for a generated one.
- A non-ASCII character in source text, or a comment or string containing a closing bracket, could crash the analysis of several rules (EXP03-C, EXP39-C, EXP46-C, EXP47-C, FIO02-C, FIO17-C, ARR00-C, MEM05-C, PRE08-C, STR31-C, DCL23-C, EXP33-C, MSC01-C). These are now handled. STR31-C also measures string literals correctly when non-ASCII text comes earlier on the same line.
- Declarations and definitions that follow a construct the parser cannot place (such as a macro that expands to a `case` label) are now seen by the file-scope constant, global and null-state analysis and by global-declaration lookup; for example, a division by a file-scope constant plus one is no longer reported as unguarded.
- A goto label written as the last line of an #if block (one with no #else) no longer makes the parser run the block past the end of its function, which hid that function, and sometimes the rest of the file, from analysis.
- EXP33-C treats a call as an allocation only when the callee is a standard allocator or one declared in `[environment.allocators]` (or `--allocator`), reached directly, through a `#define` alias, or through a function-like macro. A function is no longer taken for an allocator because its name contains `malloc`, `calloc` or `realloc`, or because its body returns `realloc`'s result; declare such wrappers to keep their findings.
- ARR30-C and the INT30-C/INT31-C/INT32-C checks use the range of values every caller passes to an integer parameter, including a loop counter's proven range, instead of treating a counter stepped in a loop as a constant; this removes false reports such as indexes that a caller's loop provably keeps in bounds, and reports values that the old constant reading had hidden.
- --diff now finds untracked C files inside an untracked directory, and reads the right files when run from a directory other than PATH.
- --detect-relevance no longer turns off the concurrency (CON) rules just because it found no thread library; on interrupt-driven firmware those rules catch state shared between the main loop and an interrupt handler.
- --detect-relevance --write-manifest now carries the policy and environment settings given on the command line (such as --environment freestanding) into the generated manifest, so a scan with that manifest uses the same settings instead of defaulting to hosted.
- A prescan cache saved under a `--rules` subset now serves any rule set the way a fresh prescan would. Before, loading one saved without a value-range rule could change INT32-C findings.
- MSC07-C now decides which calls never return the same way the control-flow rules do: `exit()`, `abort()` and the other standard functions end a block only when the declared environment provides the C library (not under the pedantic preset with no library declared); a project's own `_Noreturn` functions and wrappers that always exit now end a block too; and the Windows `ExitProcess`/`ExitThread` no longer do.
- A call to a function named like a standard library one that never returns (`exit`, `abort`, ...) now ends a path only when it really calls the library function: not when the file defines its own function by that name, and not when the name is a function pointer or parameter. This affects INT33-C, MSC07-C, MSC37-C, API00-C and the memory rules that follow control flow; `(exit)(1)` is now recognized too.
- CON03-C now reports shared variables declared without an initializer (`static int flag;`) and every variable of a multi-variable declaration (`int a, b;`), and reads volatility and atomicity per declarator: `int *volatile p` is volatile and `volatile int *p` is not. It no longer counts a same-named local or parameter as an access to a shared variable, or a block-scope static as used by its own declaration, and no longer reports thread-local variables, locks whose type is spelled through a macro or typedef, or a function that returns a function pointer.
- INT33-C now credits a divisor check only when the check's branch always leaves (it ends in a return, break, continue, goto or a call that never returns, or an if/else that leaves on both arms), so a conditional return inside the branch, or a break that only ends a loop or switch nested in it, no longer hides a possible division by zero.
- FIO40-C reports a read of the buffer on a path where fgets() or fgetws() failed, before anything writes it, and places the finding at the call rather than at the read. It matches the buffer by declaration, not by spelling, and follows it through pointers that hold its address, so a read through a cursor pointer is found and a reset of a similarly named array does not count. A failure branch that returns, exits, resets, rereads or frees the buffer, or a buffer that is never read again, is no longer reported.
- FLP30-C uses CERT's definition of a loop counter: a floating-point operand of a for, while or do loop's controlling comparison that the loop changes by a fixed amount, with typedefs such as float_t resolved. A floating variable that a for initializer declares but the condition never tests is no longer reported.
- STR11-C reports an explicit bound on a character array initialized by a string literal unless the bound leaves room beyond the terminator, with separate messages for a bound that is too small, one that drops the terminator, and one that only restates the literal's size; the last is reported only where the declaration itself could omit the bound. It measures string literals as the compiler lays them out (encoding prefixes, octal and hex escapes, adjacent literals) and evaluates macro, enumerator and suffixed bounds, so wide or escaped literals that fit are no longer reported, and it now checks braced literals, arrays of strings, typedef'd arrays and structure members. An exact-fit array declared `__attribute__((nonstring))` or `[[gnu::nonstring]]` is accepted as deliberately not a string.
- INT33-C now credits a zero check only where it holds at the division, so a division inside the zero branch, after an early return pointing the wrong way, after a guard on another variable or under an unrelated condition is reported; a guard inside a switch case, or a function's divisor parameter that every caller of a static function passes as a non-zero value, now counts.
- MEM04-C reports realloc whose size is not proven non-zero, and malloc, calloc and aligned_alloc only when the size comes from input or a parameter and nothing in the function proves it non-zero; a constant zero size is reported for all four. Sizes from enumerators, strlen(s) + 1 and > 0 or < 1 guards are proven; n * sizeof(T) is not exempt, and allocator macros are read through their expansion.
- STR30-C reports a write through a pointer that may point into a string literal, traced through assignments, aliases, search results, array elements, struct members and callees; it no longer reports a literal passed to a function because of the function's name, a scanf format, or a declaration alone.
- CON31-C no longer reports a mutex destroy in a function just because it isn't main(): a destructor, or a function that joins its threads before destroying, is not reported.
- INT30-C and INT32-C no longer report a decrement inside a do-while loop whose condition keeps the value in range, such as a countdown that stops at zero.
- FIO46-C follows control flow, so a stream closed only on a branch that returns or exits is no longer reported as used afterwards, and it reports uses of stdin after fclose(stdin) through scanf, getchar and the like.
- A double fclose() is now reported by FIO46-C instead of FIO24-C. FIO24-C no longer reports double closes of any kind, so a double close(), closesocket() or CloseHandle() is no longer reported.
- MSC30-C no longer reports a call to a project's own rand() (a definition, a macro, or a function pointer named rand), and now reports (rand)().
- The concurrency rules no longer read a call as the C or POSIX library's when the file #defines a macro of that name, and CON33-C no longer reports a function the project defines itself or a pointer named like a library function.
- CON33-C now reports ATOMIC_VAR_INIT, which its table always listed but its lowercased name match could never find.
- A declaration using the C11 keyword _Thread_local is read correctly: rules no longer report an object named `int` (DCL36-C, DCL40-C), and the object's own name and type are seen.
- CON07-C no longer reports compound operations on thread_local, _Thread_local or __thread objects, which no other thread shares.
- A suppression written for a line the parser repairs before reading (an empty export macro, or _Thread_local) now matches that line.
- A `continue` in a `do` loop now goes to the loop's condition, as C specifies, not back into the body. EXP34-C now reports a null dereference after such a loop, and MSC13-C and INT34-C no longer report on that path.
- A suppression generated for line 1 of a file with a UTF-8 byte-order mark, or for any line of a Latin-1 or UTF-16 file, now matches. The interactive UI keeps a file's byte-order mark and line endings when it inserts a suppression, declines to rewrite a file that is not plain UTF-8, and lists any file it left unchanged.
- ARR30-C reads an index that is decremented or compound-assigned before the access at the access, so `i = 4; while (i > 0) { i--; a[i] = 0; }` on a 4-element array is no longer reported as index 4, and `i = 6; i -= 1; a[i]` is no longer taken as safe.
- aurora-lint now resolves #include "..." in the including file's directory even without -I, so a plain scan of a directory knows which of the project's headers each file includes, and rules that depend on that (PRE31-C, DCL31-C, MSC30-C, FIO46-C and others) give the same answer they give with -I. A scan without a search path now also prints the line naming the headers it could not find, since an #include <...> is never found without one, and says to pass -I or --compile-commands.
- EXP33-C no longer misses an uninitialized read guarded by a static variable defined in a header when an including file writes that variable and the header is found through -I.
- DCL30-C reports the address of an automatic object that escapes its function: returned, stored in a file-scope, static, extern or thread-local object, or stored through a parameter into the caller's storage, including through members, array elements, casts and compound literals. It no longer reports a local pointer just because it is returned or stored, whatever it points at. A store reset before the function leaves is not reported.
- MEM01-C now reports a global, static or member left set after free(), passing the object a freed member lives in to a call, and calling a function the project defines while a global or static still holds the freed address.
- MSC37-C no longer reports a function whose loops are left only by `return`, or one whose return type is a typedef of `void`; it now checks functions returning `void *`, and a `switch` with no `default`.
- MSC37-C credits C23 unreachable() only when the C23 edition is declared, and exempts only a hosted int main.
- MSC37-C no longer reports a function whose paths all end in a call to a function declared noreturn: the standard `_Noreturn` and `[[noreturn]]` count under every preset, even when spelled through a macro, and so does a function-like macro whose every definition is a call to such a function.

- FIO47-C no longer reads a hexadecimal constant such as 0xE0 or 0x1e5 as floating point.

CERT gives no list of signals, so `raise(SIGTERM)` and `raise(SIGABRT)` are now reported; before, only nine signals such as `SIGUSR1` and `SIGALRM` were. Registering a handler, and `kill()` aimed at another process, are no longer reported.

POS38-C recognizes open() by its callee and a descriptor's use by its declaration, so popen(), the descriptor's name inside a string, and a shadowing local no longer count. Under the default and strict presets, MSC17-C treats a case section that ends in a call that never returns (exit(), abort(), longjmp(), a _Noreturn function) as finished; under any preset, a section that ends in an endless loop is finished. MSC06-C no longer reports clears through a project's own memset(), of static, extern or file-scope objects, or of a buffer read again after an inner block or still held by a loop's next iteration, nor spin loops on flags declared _Atomic (qualifier or _Atomic(T) specifier) or constexpr; a spin loop whose flag merely shares its name with an unrelated volatile declaration is now reported.
- EXP00-C, EXP16-C, EXP35-C and FLP07-C no longer report a construct that isn't there. EXP00-C skips a comparison already grouped by parentheses or a call's arguments, and `x | 0`. EXP16-C skips a local variable or parameter that shares a function's name, and leaves a discarded comparison such as `x == 2;` to MSC12-C. EXP35-C skips a scalar member of a function's returned struct and an element read by value. FLP07-C skips a call that returns no floating type, or already returns long double, and a name that merely contains the target's (`t` in `total`). It also accepts CERT's compliant form, in which the called function casts every value it returns. EXP00-C and EXP16-C now report once a construct they used to report twice.
- CON34-C no longer presumes that a pointer parameter passed to thrd_create() may point to automatic storage; it reports the address of an automatic or thread-local object passed to a thread creation.
- SARIF's `aurora-lint/headers` property, the `--report-headers` JSON and the `-v` listing, and the path of an input the scan refused, give a path under the current directory relative to it, as text output gives finding paths, so the same tree scanned from its root writes the same report wherever it is checked out; paths elsewhere, such as system header directories, are still given in full.
- DCL05-C, CON43-C, CON32-C, FIO13-C, CON41-C and FLP32-C report the 1-indexed column of the construct a finding names, in text, JSON and SARIF output. DCL05-C and CON43-C gave a column one too small, and the other four gave column 0.
- Without a prototype in reach, a call to `atof`, `strtod`, `strtof`, `strtold`, or any C90 `<math.h>` function or its `f`/`l` form (`floor`, `ceilf`, `modfl`, ...) now has the return type the standard gives it, where only sixteen math functions did before, so FLP07-C and every other check that reads an expression's type see these calls.
- FIO14-C now reports `ungetc()` on a stream that nothing has read or positioned since it was opened in the same function (file position 0), under every preset and whether or not POSIX is declared; POSIX relaxes only the rule's two `fseek()` forms.
- EXP35-C now reports `++`, `--` and `&` applied to an element or array member of a function's returned struct (`++f().a[0]`, `p = &f().a[0]`) outside a call argument; these were missed before. An address is reported only where it is stored or returned, since C11 allows it within the expression.
- DCL11-C counts a `*` field width or `.*` precision in a printf-family format as an argument of its own, so `printf("%*s", (int)n, buf)` is no longer reported as passing too many arguments. A positional `%n$` format is no longer reported as an argument-count mismatch.
- Under a declared C99 or later edition (`c_standard`, or `-std=` in a compile database), a call to a floating-point function C99 added, such as `round`, `cbrt` or `wcstod`, has the standard's return type even when its header was not expanded, so FLP07-C reports `long double x = round(d)` and FLP02-C sees a floating operand; under C89 or with no edition declared the call stays untyped.
- A compile database's `-std=` edition is now found for a file the scan names by a relative path or a path through a symlink; before, MSC37-C's C23 `unreachable()` reading and the C99 library typing missed it for those files.
- A function declared in a header after annotation macros whose argument names `return` (such as `_Success_(return == 0)`) is now read as declared, so DCL31-C no longer reports calls to it as undeclared.
- MSC17-C treats a call to C23 `unreachable()` as ending a case section when the C23 edition is declared (by `c_standard` or the compile database) and the file defines no `unreachable` of its own, as MSC37-C already does; GNU `__builtin_unreachable()` is still not credited.
- SIG31-C reports a signal handler's access to a sig_atomic_t that is not volatile, and to a type whose name only contains `atomic_`; `_Atomic` objects and a `volatile` carried by a typedef are recognised as safe.
- An `#if`/`#ifdef`/`#ifndef` between two operands of an expression statement, such as a build-time-optional `| FLAG` in a chain, is no longer read as part of the expression, so EXP00-C and EXP46-C stop reporting operators that come from the directive's condition.
- INT01-C no longer reports a parameter whose name has a size word only inside another word (`filename`, `silent`, `account`) or only in its type (`key[KEY_SIZE]`), whose type is `size_t` through a typedef, or whose spelled type cannot hold an integer size (a string, a struct, a float, a void or function pointer). It no longer reports an allocation size that is `size_t` by its declaration (a typedef of `size_t`, a `size_t` member or global, `strlen(s) + 1`), or of floating type. It no longer names an allocator's handle (`pool_alloc(pCount, nBytes)`) as the size, or a flag that follows a `size_t` size (`xalloc(sizeof(T) * n, nFlags)`). A comparison is reported only when a signed integer is compared with a `size_t`: an `int` compared with a `ssize_t`, or with an `int` that shares the name of a `size_t` declared in another block, no longer is.
- MSC40-C no longer reports an `extern` function definition, or one with `inline` only inside a name or an attribute such as `noinline`, as a non-static inline function; a definition is inline only when it carries the `inline` function specifier, and a `static` written after `inline` or spelled through a leading macro counts as static.
- EXP19-C now reports an unbraced `else` body that follows an unbraced `if` body; before, only the `if` was reported.
- EXP39-C no longer reports reading a field of a structure inside a union after writing another member, pointer arithmetic from a struct member's address, or a cast whose operand it could type only from its name (such as `fputs` read as a float because it starts with `f`). A cast is reported only when the operand's type comes from a declaration in the same file; a struct member, or a variable declared only in a header, is not typed and is not reported.
- PRE31-C judges a macro invocation only by the definitions that can be compiled with it: a definition in another branch of the same `#if`, or one that needs an `#ifdef`/`#ifndef` state the invocation's own conditionals exclude, is no longer held against it, and where no definition can apply the call is treated as a function call. The C library's `assert` and `getc`/`putc` family keep their library reading.
- A function-like macro defined under a guard that the file itself defines only in some builds (`#if defined(WIN)` / `#define USE_FN` / `#endif`, then `#if !defined(USE_FN)`) is no longer read as dead code, so PRE31-C and the other checks that read every definition of a macro judge it as the definition those other builds compile.
- PRE31-C reads `(T)(x)` and `(T) (a + b)` as a cast rather than a call when `T` is a type keyword, an object-like macro naming a type, or a typedef or typedef alias in scope where the cast is written, from the file or a header it includes (one outside the project included), so the strict preset no longer reports it as a call with unknown effects; a parenthesized compiler builtin such as `(__builtin_expect)(v, 1)` counts as the builtin. A call written with the function's name in parentheses, such as `(getc)(fp)` or `(step)(v)`, is judged as a call to that function, as C requires, not by a macro of the same name, and a call of a function the file declares, such as `foo_t(v)`, is not read as a cast because of a `_t` suffix or another file's typedef of the same name.
- PRE31-C reads macro arguments more exactly. It splits an invocation's arguments the way the preprocessor does, so a two-word type argument such as `cast(unsigned long, x)` counts as one argument, later arguments get the right numbers, and an argument cut short by the closing parenthesis is quoted as written. It no longer reports a type-generic macro that evaluates its argument once in whichever `?:` arm runs, such as an `isnan`-style dispatch `sizeof(x) == sizeof(float) ? f(x) : g(x)`; an argument evaluated in only one arm, twice on some path, or right of `&&`/`||` is still reported. Under the default preset too, it now reports an argument that calls a function whose body calls a side-effecting function through parentheses, such as `(bump)(1)`.
- STR04-C no longer reports a `signed char` or `unsigned char` buffer passed to `memcpy`, `memmove`, `memcmp`, `memset` or `memchr`; those functions take bytes, not strings.
- DCL20-C reports an old-style function declaration whose declarator is wrapped in a pointer or parentheses, such as `char *f();` or `char *(*fp)();`; it reported an empty parameter list only when the function declarator was the declaration's outermost declarator.
- FLP00-C types a comparison's operands by their declarations, so `==` and `!=` between `float`, `double` or `long double` values, whether variables, members, typedefs or function results, are reported, and a call to a file's own integer-returning function named like a math function (`int sqrt(int)`) is not. Under the default policy every spelling of an exact zero (`0.0`, `-0.0`, `0.f`, `0`) is exempt.
- DCL37-C no longer reports defining a feature-test macro that a standard or glibc documents for programs to define (`_GNU_SOURCE`, `_POSIX_C_SOURCE` and the rest of a closed list of feature-test macros documented by ISO C, POSIX and glibc), in every preset. The exemption covers the name only, as an object-like `#define` with any value; the value is not checked. A function-like definition of a listed name, a lookalike such as `_MY_SOURCE`, a definition of `__STRICT_ANSI__`, and include guards such as `_FOO_H` are still reported.
- DCL37-C no longer reports a block-scope identifier such as `_x`, a `for (int _i ...)` counter or a block-scope `extern int _x;` as a file-scope identifier.
- EXP37-C no longer reports function declarations: an old-style declaration with an empty parameter list, a variadic prototype, or a function pointer declared with `()`; DCL20-C reports old-style declarations. Calls through an incompatible function pointer, and calls without a prototype that don't match the definition, are not reported yet.
- EXP19-C no longer reports a body that is braced in every preprocessor configuration, an `if` whose condition is split across `#if`/`#else` arms as the body of another, or a `do` body after a `#pragma` arm as an empty `while` body.
- STR04-C reports a `signed char` or `unsigned char` array or pointer passed to a string function when it is a local variable or a parameter, as in CERT's example; it only recognized file-scope variables. It no longer types an argument from another declaration of the same name.
- DCL20-C no longer reports a call that follows a function-like macro expanding to a statement (`CHECK(a) act();` with `#define CHECK(x) if (x)`) as an old-style declaration of the called function, and it now reports an empty parameter list on a function declarator inside another (`int (*getf())(void);`).
- PRE31-C judges `assert`, `getc` and `putc` by the definition in force at the call. A project header that does `#undef assert` and defines its own, in one build or in each branch of an `#if`, replaces the library's `assert`, and each of its definitions is judged, unless `<assert.h>` is included again afterwards. A header reached only in some builds leaves the library's reading in force for the others; an `#include` in the same `#ifdef` branch as the call, or in a source file wrapped whole in a feature `#ifdef`, is not one of those.
- Rules that read a macro's definitions, PRE31-C, MSC37-C and MEM01-C among them, read a default value defined in the #else of an #if 0 that has no #elif, or under #if 1, as defined in every build, and read a name that an #undef removes and the very next directive defines again as still defined.
- DCL37-C now checks typedef names, enumeration constants, struct, union and enum tags, structure members, labels, every declarator in a declaration (including a function pointer's parenthesized name), and functions defined at file scope. A name beginning with an underscore is reported where C reserves it, at file scope for ordinary identifiers and tags. A name reserved for any use (`_X`, `__x`) is reported in every scope, once per declaration.
- DCL37-C no longer reports a reserved macro used as an array size, such as `_MAX_PATH` in `char path[_MAX_PATH];`, as if the declaration declared it.
- DCL37-C no longer reports a library name such as `bool`, `true`, `false`, `NULL`, `FILE`, `EOF`, `SIZE_MAX` or `INT_MAX` in a file that includes none of the standard headers defining it, since C reserves those names only with one of their headers. `#define bool char` in a file without `<stdbool.h>` is no longer reported. `errno` is still reported everywhere.
- DCL37-C reports `#undef` of a name reserved for any use (`_X`, `__x`), including a feature-test macro such as `_GNU_SOURCE`, since C makes removing such a macro undefined. `#undef NULL` and other library macros are not reported.
- Under the default policy, FLP00-C no longer reports a floating-point comparison with a zero cast to an arithmetic type named by its keywords other than _Bool (`x == (double)0`), or with an object-like macro that is an exact zero in every build reaching the comparison (`#define ZERO 0.0`, or a cast or parenthesized zero), including one from a header included before it; it treated only a zero literal or '\0' as zero. A macro some build may define otherwise, such as an `#ifndef` default, is still reported. The strict and pedantic policies report all of these, as they report a comparison with a zero literal.
- A storage-class macro such as `#define STATIC static` is now read as the keyword it expands to wherever every definition of it that the file can see agrees, so `STATIC myint f(void)` is no longer reported by DCL15-C or DCL19-C as needing to be static, and `STATIC struct { ... } s;` is no longer read as a function by MSC37-C or its members as unused locals by MSC13-C. A macro left empty or overridable in some build configuration keeps its external-linkage reading there, and a macro name shorter than its keyword, or one expanding to more than the keyword (`static inline`), is not yet read this way.
- EXP19-C reports a split `if` nested inside another `#if` chain once, at its body, rather than once per arm, and an unbraced body whose first preprocessor arm is `#if 0` is no longer missed.
- A control header alone in an `#if 0` block, such as `#if 0` / `if (p)` / `#endif` / `{ … }`, no longer makes any rule read the statement after the `#endif` as that header's body, or lose the function's `return` when there are two such blocks.
- On files with Windows (CRLF) line endings, the steps that set preprocessor conditionals aside before parsing placed their edits a few bytes early on every line, which could hide findings (sometimes every finding in a function) or report ones that were not there. They now place them where they do on the same file with Unix line endings.
- aurora-lint now scans a C header that names a variable or parameter `new` or `delete`, or that holds an expression statement such as `a & b;`. It took such a header for C++ and skipped it, so it reported nothing in the header and left the header's definitions out of the cross-file analysis. One C++ shape is now read as C: a header whose only C++ is a reference beside an unexpanded macro, as in `API_EXPORT int& f();`.

### Removed

- MSC42-C, POS55-C and WIN05-C are no longer reported under those ids, because none of them is a CERT C identifier. MSC42-C and POS55-C now report unchanged as CWE-327 and CWE-666; WIN05-C's unquoted-path check reports as CWE-428, and its registry check, now limited to writes under HKEY_LOCAL_MACHINE or HKEY_CLASSES_ROOT, as CWE-272. - FIO51-C is removed: CERT C has no FIO51-C (it is CERT C++'s FIO51-CPP). FIO42-C reports the same file left open.
- ERR06-C, FIO03-C, FLP05-C, INT14-C, MSC14-C, PRE12-C, PRE13-C and STR03-C are removed: each depends on the programmer's intent, or has no check precise enough to ship. A configuration that still names one loads with a warning giving the reason.

- DCL22-C is removed: whether an object can change asynchronously is not marked in the source. SIG31-C reports a signal handler's non-volatile shared objects and MSC22-C a local changed between setjmp and longjmp.

## [0.6.0] - 2026-10-05

### Added

- Policy and environment settings. `--profile default|strict` (or `profile` in the manifest) picks a preset, and `--policy default|strict`, `--environment hosted|freestanding`, `--libc` (iso-posix, glibc, musl, newlib, picolibc, custom) and a repeatable `--set NAME=VALUE`, or the manifest's `[policy]` and `[environment]` tables, override it option by option. The default preset is the default policy on a hosted environment; strict is the strict policy on a freestanding environment with no libc model, for teams that trust nothing a build or platform could take away (an assert that NDEBUG strips, `_Noreturn`, free(NULL) being a no-op, the standard library's exit functions). `--list-options` shows every option under each preset and the current settings, and a SARIF report records the resolved settings and their hash.
- ERR33-C now checks the result of every function in CERT C's table of standard library error returns, including getc, getchar, putc, setvbuf, the wide-character input/output and conversion functions, the search functions, the C11 threads functions and the Annex K functions, each against the error return CERT gives for it. Results that CERT's exception EX1 says need not be checked (puts, putchar and their wide counterparts, and wide output to stdout or stderr) are still not reported.
- `[environment.allocators]` / `[environment.deallocators]` in the manifest, and `--allocator NAME[=CONTRACT]` / `--deallocator NAME[=ARG]` on the command line, declare memory functions the scan has no body for. A declared deallocator frees the argument it names, and a declared allocator follows the named standard allocator's contract. The memory-lifetime rules read the declarations. A manifest's declarations also apply under `--profile`, and they enter the settings hash only when set.
- New `--exclude-all` leaves matching files out of everything: they are not scanned, nothing is reported in them, and their definitions no longer feed the cross-file facts other files are checked against, so a test stub or example program no longer stands for the real function. New `--report-exclude` silences code you still want read (vendored code your product links), and `--prescan-exclude` reports files without reading them for cross-file facts; a manifest's `[scope]` table takes the same three lists as `exclude_all`, `report_exclude` and `prescan_exclude`. `--exclude` is deprecated: it keeps its old meaning, the same as `--report-exclude`, so existing command lines give the same findings, and it prints a warning naming the replacements.
- Each release's documentation is now published at https://brandon-arrendondo.github.io/aurora-lint/<tag>/ and kept unchanged, so a page can be cited as it read at that release; versions.html at the site root lists every release.
- A `data_model` (iso, ilp32, lp64, llp64) is a named bundle of integer facts, and `[environment]` can override each one by key: char_bits, short_bits, int_bits, long_bits, long_long_bits, pointer_bits, wchar_t_bits, char_signed, float_bytes, double_bytes, long_double_bytes, time_t_bytes, off_t_bytes (also via --set). A width must be a whole number of 8-bit bytes, up to 64 bits, so a `char_bits` of 9 or 12 is refused; values below the ISO minimum or out of rank order are refused too, with the key named. Declared facts are part of the settings hash.
- `--list-options` shows every integer fact with its source (cli, config, data-model:NAME, iso-floor, unknown); `--check-config` validates the manifest and command line exactly as a scan would, without scanning; `--write-config FILE` writes a complete commented configuration (refuses to overwrite without --overwrite; `-` prints to stdout).

### Changed

- Under the default preset, a function declared only with GNU's `__attribute__((noreturn))`, or with a `NORETURN` macro that expands to it, no longer ends a path unless its body is seen never to return. ISO C's `_Noreturn`, `<stdnoreturn.h>`'s `noreturn` and `[[noreturn]]` still do, as do POSIX `_exit()` and a wrapper whose body ends in it.
- API00-C no longer asks `main` to validate `argv` in a hosted environment (the default preset), since C guarantees it is a valid array there; under the strict preset `main` is checked like any other function.
- aurora-lint now refuses a manifest with an unknown top-level key or table, so a misspelled table can no longer leave a scan on default settings, and refuses a saved prescan cache written by a different version, with a message to re-create it, instead of misreading it.
- MEM06-C now reports only memory that holds a credential (a buffer that reaches a password or passphrase argument of LogonUser, crypt, PAM, a database or LDAP login, or a password-hashing call) and is not locked into RAM before the secret is stored in it; it no longer reports every allocation. It does not yet follow a buffer through pointer aliases, unions, function pointers, globals or across files, so those cases are not reported.
- PRE31-C now judges every preprocessor arm of an unsafe macro, including variadic arms and arms that only stringize an argument, and counts each use of an argument separately (sizeof/typeof/_Generic operands are not evaluations). Among library macros only assert's argument and the stream argument of getc/putc/getwc/putwc are checked. A call in the argument is reported when the callee is shown to have a side effect. An unproven call (no definition in the scan, a call through a pointer, a function another scanned file defines that nothing yet proves pure or impure, or a library function whose only effect is overwriting its own static result, such as strerror, inet_ntoa, strsignal, gai_strerror, getenv, gmtime or asctime) is reported only under the strict preset: new option pre31_unknown_call_pure and environment contract stdlib_call_effects. New options change the settings hash, so run ids recorded from this release carry a new hash.
- PRE05-C no longer reports a macro argument whose parameter the same macro definition also uses plainly (such as `assert(expr)`, which evaluates `expr` as well as stringizing it), or one passed through GNU's `, ##__VA_ARGS__`, since those arguments are still macro-expanded.
- ERR33-C applies CERT's exception ERR33-C-EX1 exactly as written. printf, vprintf, puts and putchar results may still be discarded; fprintf, vfprintf, fputs and fputc results may be discarded only when the stream is stdout or stderr, named directly or through a macro alias. Writing to any other stream without checking the result is now reported, and so is a discarded sprintf or vsprintf result. A stored result is also judged more precisely: a read through it before its test is a use, EOF must be tested as EOF, a loop condition counts for a read at the bottom of the loop, and a test inside a macro counts only when every definition of the macro makes it.
- ERR33-C findings now quote the function's error return as CERT's table states it. A `function_prefix` waiver is also matched against identifiers in that quoted text, so a waiver such as `function_prefix = "thrd_"` now also hides findings for functions whose quoted error return names a `thrd_` value (for example `mtx_*`, `cnd_*` and `tss_*`, which return `thrd_error`).
- aurora-lint now refuses an invalid suppression file instead of loading only part of it. An unknown table (such as [[suppression]] or [[wildcard]]), an unknown key (such as `reason` for `justification`), an entry with no `name`, a `hash` entry without `file` and `rule`, or an entry with nothing to match on is reported, all problems at once, and a suppression file that cannot be read or parsed stops the run with exit status 2 instead of a warning.
- MEM30-C, MEM31-C and the other memory rules count a call as freeing its argument only where the scan can prove it: from the callee's body, a macro expansion, the C library contract, or a deallocator the project declares (`[environment.deallocators]`, `--deallocator`). A callee's name alone (`*_free`, `destroy_*`, `*_cleanup` and the like) no longer counts, so a bodiless library free now leaves its argument reported as leaked until it is declared; `--report-deallocator-candidates` lists the undeclared callees that would change a finding. A callee that releases its argument on some paths only still clears a leak but no longer supports a double-free report.
- EXP34-C no longer treats a documented "must not be NULL" parameter comment, or a sqlite API's name, as proof that a pointer is non-null; such dereferences are now reported (API00-C likewise no longer credits documentation).
- Without a declared data model only what ISO C guarantees about integer widths is credited: nothing is proven or reported through a guessed width, and a defect that occurs at some conforming width is reported. Under this default, constant expressions that overflow a 16-bit int (e.g. `1024 * 1024`) are reported in assignments and arithmetic operands; declaring a data model or `int_bits` clears them. An integer constant too wide for a 16-bit int is taken to be at least 32 bits wide (int on most targets, long otherwise); an implementation with an int between 17 and 31 bits is not modelled, so declare `int_bits` for such a target.
- CHAR_MAX and CHAR_MIN are unknown unless `char_signed` is declared and CHAR_BIT is known (a data model or `char_bits`), and a proof through one is lost; no data model sets `char_signed`, and only the Windows-only `llp64` sets `wchar_t_bits`. The buffer-size checks of ARR30-C, ARR38-C and STR31-C do not follow the data model yet.

### Fixed

- FIO47-C no longer reports an invalid conversion specifier at the seam between adjacent string literals in a format string (such as "0x%04" PRIX16 "\n"); literal-only joins are validated as the single string the compiler sees.
- FIO47-C now takes an argument's type from its actual declaration, so it no longer reports a type mismatch for an integer declared on a line that also declares a pointer, one initialised with a multiplication, one whose declaration carries an attribute macro such as UNUSED, or one whose name merely contains "int".
- FIO47-C's type-mismatch message now quotes the format directive as written (for example '%-20lx' rather than '%x'), and names which part of a '%.*s' directive a mismatched argument belongs to.
- FIO47-C no longer miscounts arguments for a '*' field width or precision: in printf-family calls ("%.*s", "%*d") the '*' consumes an int of its own, and in scanf-family calls an assignment-suppressing "%*d" consumes none.
- FIO47-C no longer reports a scanf scanset such as `%[^\n]` or `%128[^"]` as an invalid conversion specifier, and no longer misreads the characters inside the set as further format directives.
- EXP19-C no longer reports a braced `else` body as unbraced when a comment sits between `else` and the body, and MSC01-C follows an if/else-if chain across comments and `#if`/`#endif` lines instead of judging each fragment separately.
- FIO30-C again reports format strings that reach a file-scoped `static` sink through a forwarding static, a local source function's return value or a static global, and follows calls made through a local function pointer.
- EXP34-C no longer reports a pointer as possibly null after a guard that assigns it inside the test, such as `if ((p = malloc(n)) == NULL) return;` or `while ((node = next(it)) != NULL)`.
- EXP33-C no longer reports reads of `static` or `_Thread_local` variables that have no initializer; C zero-initializes them, so their value is never indeterminate.
- ENV30-C no longer attributes a getenv()/strerror()-style origin to a different variable that shares a name, or to a buffer that only copied the returned text.
- MEM10-C no longer reports `sizeof(x)` as a pointer's size when `x` is a scalar, a local array, a pointer whose own bytes are being copied, or an element of an array of pointers.
- EXP33-C no longer reports `extern` declarations, array names used only as addresses (`p != buf`), buffers filled through a pointer passed by name, or variables read outside the block that declared them; and `#if __has_include(<header>)` no longer corrupts the parse of the code after it.
- MEM31-C no longer reports an array whose elements are allocated in a loop as leaked when the array is owned elsewhere: returned to the caller, stored in a field, parameter, global or static, or released by a deallocator call or unwind loop rather than a matching free loop.
- EXP34-C no longer reports a dereference guarded by an assert-style macro that no build configuration compiles out, such as one that calls abort() or exit() when its condition is false. Macros with an NDEBUG arm, and checks switched on at run time, still guard nothing.
- FIO05-C output is deterministic, and it no longer reports a reopen when the two opens sit in opposite arms of an if, or when a reused handle's close was filed under the wrong file.
- EXP34-C no longer reports a pointer argument as null when it was reassigned (for example from a function call) after being set to NULL, and it now recognizes an allocation checked with exit() or abort() as non-null.
- EXP19-C no longer reports an if/else body written as a macro invocation with no semicolon whose expansion is a braced block, nor the `} while (0)` that closes a do-while inside a multi-line #define containing a comment.
- Rules no longer take what a function's visible callers pass as proof about its parameters unless every caller is in the scanned source (the function is `static` and its address never escapes). Exported functions, library entry points and callbacks are now checked on their own bodies for value ranges, buffer sizes, taint and index validation, and count as possible concurrent entry points for CON03-C and CON07-C. DCL19-C no longer reports a function that another scanned file calls.
- STR38-C output is deterministic and each call is reported at most once. It takes a string argument's narrow or wide character type from that argument's own declaration, a string literal's prefix or a cast, so a variable whose name contains, or matches, another variable's name no longer decides it, and an argument whose type it cannot resolve is not reported. EXP30-C and POS53-C now name the variables and mutexes in a finding in a fixed order.
- EXP34-C no longer reports a dereference in a later operand of a condition such as `p == NULL || x || p->field`, which is reached only when `p` is non-null, and no longer takes `if (p == NULL && x) return;` as proof that `p` is non-null afterwards.
- Code inside an assert's argument is now checked: EXP34-C reports a dereference of a possibly-null pointer written in an assert, API00-C reports overflowing arithmetic there, and an assert no longer guards a dereference inside its own condition. A plain assert still guards the code after it under the default preset (EXP34-C, ARR38-C, INT33-C, FLP36-C); under the strict preset, which reads the release build where NDEBUG removes it, it does not.
- ERR33-C now credits a check only when the variable that holds a function's result is itself tested against that function's error value (NULL, EOF, a negative or short count, (T)-1, SIG_ERR, or errno/end pointer for strto*), anywhere later in the function before the variable is overwritten. The heuristics it replaces are gone: text matching over the next five statements (where `!s` counted as a test of `sz`), the error-handling-context and "stderr"-in-nearby-text exemptions, credit from assert(), and the requirement that a strto* end pointer be named `endptr`.
- The signal- and exit-handler rules (SIG00-C, SIG01-C, SIG30-C, SIG31-C, SIG34-C, SIG35-C, ERR32-C, ENV32-C) and CON03-C/CON07-C's reachability now find handlers by what is registered rather than by function name or signature. Handlers installed with sigaction() (sa_handler or sa_sigaction, by assignment or designated initializer), through a local registration wrapper or macro, or by address (&f) are now checked. Functions that merely look like handlers, and signal() calls that ignore a signal or restore a saved disposition, are no longer reported.
- Signal-handler rules (SIG00-C, SIG01-C, SIG30-C, SIG34-C, SIG35-C) now recognize handlers declared only in a header, handlers installed through a local function pointer, a file-scope `struct sigaction` initializer or a wrapper that registers several signals, and (with `-d`) a handler registered in one file but defined in another.
- MEM06-C: a lock or core-dump limit is credited only where it holds in every build configuration and on every path to the store (short-circuit and ?: branches, goto paths, #ifdef arms); more store forms are recognized (Annex K _s copies, ReadFile, getline, *p++ =), and a project function locking memory or protecting the process in every definition is credited.
- SIG30-C no longer reports a function-like macro called in a signal handler as an unsafe call: it checks what the macro expands to in every #if branch (so `UNUSED(sig)` is quiet, and a macro that calls `fprintf()` in any configuration is reported as calling `fprintf()`), and each message names the macro the call went through.
- A compile_commands.json written for an MSVC build (cl.exe or clang-cl, including behind sccache or ccache) is now read with cl's own syntax. /D, /U, /I, /imsvc, /external:I and /FI now apply to the scan; before, they were silently ignored. @file response files (UTF-8 or UTF-16) and Windows command-line quoting are handled too. cl takes its SDK and CRT include directories from the environment rather than the command line, so pass those with -I.
- PRE00-C, PRE01-C, PRE02-C, PRE05-C, PRE12-C and PRE32-C no longer read operators, parameters or directives inside string and character literals or comments in a macro definition as code; PRE02-C also reports operators written without spaces and no longer reports a replacement list that is a single call or subscript; DCL16-C and DCL18-C now check the number literals inside #define replacement lists.
- Macros, aliases and functions defined differently under #if/#ifdef are now checked in every build: a free, write, clear or null that would remove a finding must happen in every definition, one that starts a finding counts if any definition has it, a function counts as never returning only if every definition ends the process, and a macro argument that one build ignores is reported at its next use instead of at the macro call. File-scope statics are constant-folded only when nothing writes them and they have one value in every configuration, and a branch is pruned as dead only on a constant fixed in every configuration.
- FIO30-C no longer reports a format string that is a conditional expression (cond ? "a" : "b", parenthesized or not) whose two result operands are both string literals; a non-literal operand is still judged on its own.
- EXP47-C reports each va_arg that reads a promoting type (char, short or float, in any specifier order, through __builtin_va_arg, or in a macro body) exactly once, and no longer reports va_arg(ap, char *) or a va_arg written in a comment or string.
- Windows projects scanned with a compile database from cl or clang-cl now find headers the way the Windows build does, ignoring case in #include names (for example <Shlobj.h> finds ShlObj.h). --include-names exact|case-insensitive, or include_names in the manifest's [environment] table, overrides this. --report-macro-gaps lists each include spelled in a different case from its file, and each name that matches several files differing only in case. Settings hashes are unchanged unless --compile-commands names a cl or clang-cl build, or include_names is set to case-insensitive.
- A static constant that is defined differently across #if, #elif or #elifdef arms, or only tentatively in one arm, is no longer folded to a single value, so EXP33-C and FIO30-C no longer skip code that one of those builds compiles; definitions inside #if 0 are ignored.
- PRE31-C no longer reports an argument with side effects passed to a C library function the implementation defines as a macro (such as `tolower`), since C11 7.1.4 requires such a macro to evaluate each argument exactly once. The standard's own exceptions, the stream argument of `getc` and `putc`, are still reported. Set `library_macros_evaluate_once=false` to judge those macros by their definitions. A project macro defined differently in two headers is judged by the definition its file's includes reach.
- The suppression documentation and man page described [[suppression]] and [[wildcard]] tables that aurora-lint never read, so a file written from them suppressed nothing; they now describe the [[suppress]] entries it does read.
- PRE31-C now judges a function called in a macro argument by what its body does, across every scanned file. A call to a function proven to change nothing is no longer reported. A call to one proven to modify an object outside itself is now reported under the default profile too, where before it was reported only under strict. A call the analysis cannot follow keeps the profile's policy, reported under strict only. A call pasted onto a prefix with `##` (`prefix_ ## CALL`) is now judged by the function the paste produces, instead of as an argument that is never evaluated.
- FIO30-C no longer reports a comment inside a call's argument list, a cast string literal, or a parenthesized or cast format parameter forwarded to a vprintf-family function as a user-controlled format string.
- A function that frees its parameter moved by a constant (`free((T *)p - 1)`, or through a local `h = (T *)p - 1; free(h)`), or through a local copy of it, is now recognized as freeing that parameter.
- A leak, an uncleared buffer or an unclosed file is no longer excused because the called function releases, clears or closes it in only some of its definitions (in different #if branches or files); every definition the call can link with must do it (MEM31-C, MEM03-C, MEM30-C, FIO42-C).
- Code where an #if/#else supplies alternative parts of one condition (each arm one operand of an `if (...)`, or each arm opening the same `if` with its own brace) now parses: aurora-lint keeps the arm the scan's configuration compiles, and leaves the code unrepaired when it cannot decide (a version comparison against an undeclared macro, a compiler-reserved macro the configuration does not set). Findings in a file that such a conditional had turned into one parse error are now reported, and findings that read the wrong arm are gone.
- EXP34-C now reports a dereference that precedes a later NULL test of the same pointer, a NULL passed to the `%s` conversion of an ISO C or POSIX formatting function (or a project formatter whose body proves it forwards to one), a function-like macro that dereferences a possibly-null pointer argument, and a pointer read after a status check that the callee's own body does not prove sets it; an earlier NULL test whose NULL branch does not leave is no longer a guard.
- EXP34-C no longer reports `&*p`, `&p[i]` or a pointer printed with `%p` as a dereference, the result of a function whose every return is provably non-null (directly, through a local, or through another such function) as possibly NULL, or a pointer passed to a variadic function that is not shown to be a formatter.
- Integer and floating-point rules type a variable by its own declaration, so a same-named variable in an inner block or another function no longer decides whether an operation is checked.
- Floating-point and integer-conversion rules type each operand by its declaration, including struct fields, bit-field promotion and function return types, so integer, pointer and array comparisons are no longer reported as floating-point equality.
- INT32-C reports an overflow when a `long` or `long long` variable holding its type's maximum (`LLONG_MAX`, `LONG_MAX`, `INT64_MAX`) then has 1 added, which v0.5 missed.
- Under a declared data model, an `unsigned long` constant is typed at the model's long width: `(1ul << 56) - 1ul` under lp64 is no longer reported.
- EXP33-C and EXP34-C no longer take minutes on very deeply nested code, such as thousands of nested `if` statements; the time to resolve an identifier no longer grows steeply with nesting depth.

### Removed

- `--export` now writes only SARIF (`.sarif`, `.sarif.json`) and JSON (`.json`); the built-in CSV and XLSX output, including the interactive UI's save dialog, is removed. `scripts/sarif_convert.py` converts a SARIF report to CSV, or to XLSX with `openpyxl`, in the former column layout.
- The per-rule `category`, `cert_id` and `parameters` manifest keys, which had no effect, are removed; a manifest that sets them still loads, with a warning.

A `#define` in real source still overrides a build flag, and findings are never suppressed by configuration.

- EXP33-C no longer reports an output variable as possibly uninitialized after the caller has checked the return value of a function that writes it on every successful path.
- Calls inside code the C parser recovers only partially (for example, after a macro that expands to a `case` label) now count as callers.
- MEM30-C no longer reports a double free or use-after-free of a struct member that an intervening memset() set back to NULL.
- A pointer passed by address to a function that writes it on only some paths is no longer assumed non-null after the call.
- MEM30-C no longer reports a double free or use-after-free of a struct member after the pointer it hangs off has been pointed at a different object.
- ENV03-C, ENV33-C, INT30-C to INT32-C, STR02-C and FIO30-C no longer treat a comment or string literal that mentions `getenv()` as a source of tainted data.
- A `static` function whose address is taken is no longer treated as though every caller were visible, so a call through a function pointer can no longer be overlooked when proving a parameter non-null.
- MEM30-C no longer reports a double free or use-after-free on a path that a status variable, set alongside the free and tested later, rules out.
- API00-C again reports a function that passes an unvalidated pointer parameter to a helper whose only use of it is taking a member's address (&p->field), a case missed since 0.5.2.
- MEM30-C now recognizes a single-argument deallocator that releases memory through a function pointer, so a use-after-free or double free after calling it is reported instead of silently missed.
- EXP34-C no longer reports a variadic argument as dereferenced when its format conversion only uses the pointer's value (such as `%p`).
- MEM30-C no longer reports a pointer as freed after a loop that frees it on each iteration and exits because the pointer became NULL; a loop left by `break` still keeps the pointer freed.
- MEM31-C no longer reports a finding twice when unexpanded macros make one function appear nested inside another.
- MSC13-C now reports a constant initializer that every path overwrites before reading it. It no longer exempts one because it is a named constant or a literal on the returned variable.
- MEM01-C no longer reports a use after free when the freed pointer is rebound by an output-parameter call whose return value is stored, declared, returned or cast (e.g. `len = format(&buf, ...)`).
- MEM30-C now marks a double free for manual review when either free was inferred from the deallocator's name alone, and keeps that mark on a use-after-free reached through a chain of pointer copies.
- A parameter forwarded through a relay function is no longer proven non-null just because most of the observed callers pass a non-null value.
- DCL18-C now states the correct decimal value for an octal constant with an integer suffix (017L is 15, not 0), and no value for a literal whose digits are not octal.

- FIO50-C no longer treats integers shifted with `<<` or `>>` as stream input and output, and reads the stream from the correct argument of `fread()` and `fputs()`.

A `void *` parameter cast to a local pointer is still the parameter: writes through the local and null checks on it count, and `sizeof(*local)` is not a dereference.
- Cross-function null-state propagation now runs until it converges, instead of stopping after three passes. Findings that depend on a chain of forwarding calls no longer depend on where the analysis happened to stop.

## [0.5.1] - 2026-09-19

### Fixed

- Findings are now emitted in a fixed order regardless of `--jobs`, so two scans of the same tree export byte-identical files.
- MEM30-C and MEM31-C model control flow more faithfully: a branch that ends in `return`, `goto` or a call that never returns no longer carries its freed or allocated state into the code after the `if`; a loop is left through its `break`s and `continue`s as well as its condition; the `else` arm starts from the state before the `if`. This removes double-free, use-after-free and leak reports that only existed on paths the program cannot take.
- MEM30-C no longer reports use-after-free when the pointer is reassigned from the call's own result (`x = f(x)`), refilled through an out-parameter, or handed as a callback to a registration function; a deallocator is no longer recognised by its name alone when its body shows it frees only fields or nothing; `X_free(obj)` after `X_init(obj)` is not a release of `obj`; and "stack pointer escape" fires only when a global actually takes the address of automatic storage.
- MEM31-C credits a free made in a cleanup label through any callee the pre-scan saw free, cast or not, and an allocator whose result is stored by the callee it links is treated as borrowed rather than leaked.
- INT30-C and INT32-C resolve signed typedef chains, type a compound assignment from both operands, check a 64-bit signed operation against a 64-bit limit rather than `INT_MAX`, and accept a guard in an earlier operand of the same `&&`/`||`. INT30-C no longer reports a `calloc()` product of compile-time constants, or an overflow at a width it cannot determine.
- DCL05-C recognises a pointer typedef by its declaration rather than its spelling and reports the `const` applied to it; it no longer reports every callback parameter, only a declarator returning a pointer to a function.
- DCL06-C no longer reports a literal that an assertion pins to a named quantity, a literal used through `sizeof buf` / `sizeof(x.name)`, or a version check made through an accessor call.
- DCL13-C recognises a write to an array element made through a macro that assigns its parameter.
- ENV01-C reports a `getenv()` value reaching an unbounded copy, not every `PATH_MAX`-sized buffer.
- EXP34-C no longer treats the left operand of `||` as known true at the right operand, which had hidden a possibly-null dereference there.

### Added

- `aurora-lint` is published on crates.io: `cargo install aurora-lint`.
- Prebuilt macOS (Apple Silicon) binaries alongside the Linux and Windows builds, `.deb`, `.rpm` and AppImage packages.
- `--report-macro-gaps[=FILE]`: after a scan, report where the macro-expansion engine was blind -- definitions it skipped, `#include`s it could not resolve, calls it could not expand -- as a summary and optionally as JSON. It never changes a finding.

### Fixed

- A scan with no `-d` now pre-scans its own target, so a single-directory scan gets the same cross-file context a `-d` scan gets.
- Parsing is more robust: NUL-strewn input (BOM-less UTF-16, binary) no longer stalls the parser; whole declarations, casts and split control-flow headers are recovered from the parser's ERROR nodes; and rules no longer read preprocessor text as C -- an `#ifdef` guard name is not a callee, a `#if` condition is not runtime code, `defined` is not a side effect, and an operator inside a string literal is not an operator (EXP02-C, EXP13-C, INT33-C, PRE31-C, PRE32-C).
- API00-C honours a documented non-NULL precondition on a parameter (a `\param` block saying it must be initialised or non-NULL) as validation placed on the caller, no longer infers a contract from "every visible caller passes non-NULL", and no longer counts an `assert`-only use, a defined unsigned shift or pointer arithmetic as an overflow site.
- MEM30-C and MEM31-C rebuilt their ownership model: a block stored through an out-parameter, field, element or offset has escaped; every alias of a block inherits what happens to it; `p = NULL` ends that name's claim; two different deallocator names on one pointer is teardown, not a double free; a free through a freeing macro, a named wrapper or a `void **` wrapper is credited; a cleanup label reached by `goto` is entered with the state its `goto`s carry; and a free only guessed from a callee's name no longer produces a use-after-free or leak report when the callee's body says otherwise.
- MSC13-C no longer reports a defensive initial value (`int ret = SOME_ERROR_CODE;`, or a literal initializer on the variable the function returns) as a dead store; MSC37-C and MSC07-C treat labels, `case`s and preprocessor arms as control flow, so `goto`-cleanup-then-return and `#if`/`#else`-exhaustive returns are no longer reported.
- EXP43-C judges aliasing by the callee's `restrict`-qualified parameters, not by a call passing one object twice; ARR01-C reads `sizeof(ptr->member)` and `sizeof(*ptr)` correctly instead of as a decayed pointer.
- INT30-C, INT31-C and INT32-C derive parameter provenance from the call graph, recognise overflow guards by dominance rather than spelling, check at the width the arithmetic is performed in, and no longer read pointer arithmetic as integer arithmetic; INT08-C, INT16-C and INT34-C answer from value-range analysis and scope-resolved declarations instead of a fixed width or a name.
- ERR33-C no longer exempts an unchecked `fclose()` in "cleanup context"; it is reported like any other unchecked result.
- EXP02-C, EXP10-C and EXP14-C recognise side-effect-free guards, count only genuinely unsequenced calls, and resolve the operand's declared type; EXP33-C and EXP34-C credit more output-parameter shapes, distinguish MUST from MAY writes, consult the call-site null vote per call, and prove non-nullness from bail-out guards and loop bounds.
- ARR30-C credits a size guard that precedes the access, sizes a subscript against the declaration in scope, and reports the right size, line and `#ifdef` branch; ARR36-C no longer treats a parenthesized expression, a field path, an integer holding an address or the other arm of an `#ifdef` as a distinct array.
- Smaller misfires fixed in DCL06-C (hex/octal literals, value-echo tables, version-macro comparisons), DCL31-C (typedef'd function-pointer parameters, macro-wrapped declarators), FIO47-C (`snprintf` argument positions), INT01-C, MEM03-C, MSC12-C (`volatile` busy-waits, interface stubs, parser misparses), PRE31-C, WIN04-C and WIN05-C.
- Value-range analysis widens `&var` arguments wherever the call sits, applies a `for` loop's own init and update clauses, treats a branch whose condition contradicts its incoming range as dead, and bounds `rand() % n` to `[0, n-1]`.

## [0.4.84] - 2026-07-08

### Added

- `--exclude GLOB` (repeatable): exclude files matching a path glob from analysis, e.g. `--exclude '**/onelua.c' --exclude 'testes/**'`.
- `suppress.toml`: one suppression file for both the ignore surface and per-line suppressions, auto-detected in the project root (the legacy `.sqc-suppress.toml` is still read).

### Fixed

- Stack-overflow and slice-index crashes on large real-world trees; the deep-recursion rules (API00-C, API02-C, DCL01-C, DCL30-C, FIO22-C, FLP03-C, INT30-C, INT32-C, INT33-C, MEM03-C, MSC37-C, PRE13-C, SIG00-C, STR02-C, ARR38-C) were rewritten onto explicit stacks and every rule's AST walk is iterative.
- Duplicate findings: DCL02-C reported one line up to 100 times, POS37-C and SIG31-C reported each finding twice, and FIO42-C reported the same handle as both an unclosed `FILE *` and an unclosed descriptor.
- MEM30-C clears freed state on a fresh declaration, on pointer reassignment and on reassignment to an allocator wrapper, no longer aliases value copies, ignores `realloc` self-assignment on a struct field, treats `goto`/`break`/`continue` as branch terminators, gates union member aliasing on genuine unions, frees only the last operand of free-like calls, and no longer infers a double free across preprocessor conditionals.
- EXP34-C no longer reports a dereference guarded by a precondition `assert`, in a `sizeof`, or on an out-parameter whose call returned success; parameters are seeded non-NULL from `&x` call sites, and error-path null votes are dropped from the seeding.
- STR31-C resolves buffer sizes across functions, through `ALLOCA`, pointer aliases, `memset` content length, indirect `strlen`/`wcslen` `calloc` sizes and parenthesised `malloc` arithmetic; ARR30-C gates string-copy findings on source content length and detects tainted blob-decode loops and parameter-decoder over-reads across functions; FIO30-C tracks format-string taint per function.
- ARR00-C resolves array bounds from the AST declaration rather than a text scan, so braced, designated and `{0}` initializers no longer yield a false out-of-bounds; FLP06-C detects integer arithmetic on the AST and suppresses it when all operands are float; INT33-C skips float division; DCL00-C no longer recommends `const` for a variable modified later in a branch or loop; FIO42-C classifies openers by callee name, not substring; DCL15-C and INT34-C no longer report on single-file analysis or constant shifts; INT34-C proves bitmask-bounded shift amounts safe.
- INT32-C checks 16-bit and `char` operands at their own width, parses char literals, and models `switch` bodies conservatively; value-range analysis narrows the `== false` branch to the non-excluded value.

### Removed

- The interactive terminal UI is no longer in the default build. It is an opt-in Cargo feature: build with `--features tui` to keep `--interactive`.
